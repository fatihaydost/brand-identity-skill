# 브랜드 아이덴티티

당신이 디자이너다. 스크립트는 무엇이 잘못되었는지 측정하고, 무엇이 좋은지는 당신이 판단한다. 색상, 글꼴, 심벌에 관한 설명은 스크립트로 측정한 결과인지, 디자이너의 판단인지 구분해야 한다. 브리프는 브랜드의 목표·대상·조건을 정리한 작업 문서를 뜻한다.

## 1 사전 확인: 꼭 필요한 질문을 한 메시지로 묻기

다음을 한 메시지로 묻는다. 사용자나 사용자의 사이트에서 이미 답을 얻은 항목은 생략한다.

- **로고, 타이포그래피, 팔레트** 각각의 처리 방식: `new`(새로 제작) · `refresh`(기존 것을 발전시킴) · `keep`(그대로 사용) · `none`(사용하지 않음).
- 세트 수: **3**개가 기본이며, 2개·1개·4개도 가능하다.
- 사이트 URL 또는 파일, 브랜드에서 사용하는 언어, 제품에서 숫자를 표시하는지 여부.
- 아직 모를 때만: 업종, 대상 사용자, 특성 세 가지, 경쟁사 3–5곳.

사이트가 있으면 먼저 `site extract`를 실행하고, 결과만으로 알 수 없는 내용만 질문한다. 자세한 내용은 `references/discovery-brief.md`를 참고한다.

## 2 작업 흐름과 턴 계획: 중간 검토까지 약 16–20턴

스크립트 실행 형식은 `python3 <skill>/scripts/brand.py <command>`이며, 각 명령에서 `--help`를 사용할 수 있다. 서로 독립적인 명령은 한 턴에 묶는다. uv를 사용하면 스크립트가 필요한 패키지를 직접 가져온다. `check`가 누락된 패키지를 보여주면 해당 설치 명령을 사용자에게 안내한다.

1. `check` + `init NAME --sets 3 --langs en,tr [--numbers] [--site URL] [--state logo=keep …] --sector … --audience …
   --attributes a,b,c --competitors x,y --tagline … --sentence en='…' --sentence tr='…' --nav A,B,C --cta …
   [--source logo=file.svg --source palette=#hex,#hex]`를 한 턴에 실행한다. 문장(브랜드 사용 언어마다 하나), 내비게이션, CTA는 서체 견본과 목업에 사용할 실제 브랜드 문구이며, 브랜드의 어조를 반영한다. `--source`에는 유지하거나 개선할 부분의 에셋을 지정한다.
2. `references/cohesion.md`, `type.md`, `logo.md`, `ai-defaults.md`를 읽고, 팔레트가 필요하면 `color.md`도 읽는다. 한 턴에 읽으며 총량은 24 KB 이하로 한다. 나머지 참조 문서는 해당 주제가 나올 때만 읽는다.
3. `fonts search --class … --exclude-defaults`를 실행하고, 경쟁사가 있으면 `site competitors WORK url…`도 실행한다.
4. **모든 세트를 하나의 `sets.json`에 작성한다.** 형식은 `templates/sets.example.json`을 따른다. 세트마다 아이덴티티 필드, 기준색만 정한 초기 팔레트(`brand[]` 시드, 이름, 방향), 심벌 SVG를 인라인으로 넣는다.
5. `logos WORK` → 한눈에 비교하는 이미지 모음(콘택트 시트) 확인 → 심벌마다 결함 하나 수정(`logo.defect`에 명시) → `logos WORK` → 다시 확인한다. 두 차례 진행하며, 세 번째는 필수 검사를 통과하거나 진부하게 읽히는 문제를 해결할 때만 수행한다. 세부 조정에 필요한 글자 위치는 `sets/X/logo/build/wordmark-glyphs.json`에 있다.
6. `build WORK` → `review.png` 확인 → 필수 검사에서 실패한 항목 수정 순서로 진행한다. 사용자에게 제공하는 큰 이미지인 `board.png`가 아니라 검토용 이미지를 본다. 실패한 세트만 `--sets X`로 다시 실행한다.
7. 중간 검토 결과(§5)를 제시하고 **멈춘다.** 사용자를 대신해 선택하지 않는다.
8. 사용자가 고른 뒤에는 해당 심벌의 잘못된 사용 예 1–2개를 추가하고(`references/kit.md`), `kit WORK/sets/X`를 실행한다. 긴 키트는 `--full`을 사용한다. 어떤 파일이 어디에 있는지 알려준다.

사용자가 서로 다른 세트의 구성 요소를 조합하고 싶어 하면 `mix WORK A:logo A:type B:palette --as D`를 사용한다. 기존 아이덴티티를 비평할 때는 `critique`를 사용한다(`references/critique.md`).

## 3 세트 만들기

- **세트마다 하나의 디자인 원리:** 심벌, 글꼴 선택, 팔레트를 함께 만들어내는 단일한 시각적 아이디어다. 무엇을 고르기 전에 한 문장으로 쓴다. **강조 표현도 하나만** 정해 가장 눈에 띄는 요소로 삼는다.
- 브리프에 맞춰 브랜드의 성격을 비교할 축을 2–4개 정하고 각 세트를 −2..+2에 배치한다. 세트끼리는 적어도 두 축에서 차이가 나야 하며, 같은 세트의 세 구성 요소는 축 위에서 같은 위치에 있어야 한다.
- 막연한 경쟁사 목록이 아니라 **사용자의 실제 경쟁사와 차별화한다.** 세트의 차별점을 `differs_by`에 적는다.
- **상투적 선택 점검:** 글꼴·색상·심벌 아이디어마다 “이 업종의 다른 브랜드에도 같은 제안을 하겠는가?”라고 묻는다. 그렇다면 브리프에 근거한 이유를 `defaults_used[]`에 적거나 선택을 바꾼다. id는 해당 플래그의 id 또는 로고 태그다. 적어도 한 세트는 `ai-defaults.md`의 항목을 전혀 사용하지 않아야 한다. “따뜻하게 느껴진다”, “고급스러워 보인다”는 근거가 아니다.
- `keep`으로 지정한 부분은 제약 조건이다. 새로 만드는 부분을 여기에 맞춘다. 유지할 부분이 충돌하면 제안으로 알리되, 직접 변경하지 않는다.
- 이유를 설명하며 옹호할 수 있는 세트에 `recommended: true`를 표시한다.
- 이름, 디자인 원리, 콘셉트, 선정 근거, 라벨 등 자유롭게 작성하는 텍스트는 모두 문서 언어(`init --doc-lang`)로 쓴다.

## 4 구성 요소의 완성도

**로고**(`references/logo.md`): 심벌은 브랜드를 알아보게 하는 것이지 설명하는 것이 아니다. 세트마다 한 문장짜리 아이디어 4–6개를 쓰고 하나를 구현한다. 채워진 기본 도형으로 100단위 그리드에 심벌을 그린다. 도형의 불리언 연산에는 `data-op="subtract|union|intersect"`, 색상에는 `data-color="<palette role>"`를 사용하며, `<text>`는 사용하지 않는다. 워드마크는 세트의 디스플레이 글꼴에서 자동으로 생성된다. `case`, `tracking`(1/1000 em), `tags`를 설정한다. 구조를 나타내는 태그 어휘는 `ai-defaults.md`에 있다. 매번 16 px와 32 px로 확인하고, 작게 표시했을 때 심벌이 뭉개지면 `symbol_small_svg`를 추가한다.

**워드마크만 있는** 세트도 다음 두 요소가 필요하다. (1) 아웃라인으로 변환한 글자에 `wordmark_detail_svg`로 그린, 다른 브랜드와 구별되는 디테일 하나. 워드마크 좌표는 대문자 상단 y=0, 기준선 y=100이며 x는 `data-advance` 단위다. 각 도형은 `data-op` 단계 하나이고, `data-glyph="n"`은 적용 대상을 n번째 글자로 제한한다. (2) 16–48 px에 사용할 수 있도록 디자인한 작은 심벌(`symbol_small_svg` 또는 `logo.monogram`). 기본 글꼴과 첫 글자만 딴 파비콘은 기성품처럼 보인다. 자체 `data-color`가 있는 디테일 도형은 별도 색상을 유지한다. `data-glyphs` 요소에는 `data-wght`/`data-opsz`를 지정해 작은 크기에서도 더 튼튼한 형태를 만들 수 있다.

역할 이름은 UI에 사용할 색상 단계로 해석되고, 브랜드 id(`brand-1`)는 정확한 브랜드의 16진수 색상을 유지한다. 배경에 대한 대비가 3:1 미만인 주요 부분은 해당 배경에 맞춰 정한 전경색(ink)으로 그린다. `app_icon_svg`(100단위 그리드)를 사용하면 아이콘의 바탕 타일도 아이콘의 일부로 디자인할 수 있다. 아이디어에 어둡거나 유색인 바탕이 필요하면 `card.ground`를 `dark` 또는 역할/브랜드 id로 설정해 카드에 해당 바탕이 표시되게 한다.

**타이포그래피**(`references/type.md`): 디스플레이 글꼴은 브랜드의 목소리를, 본문 글꼴은 읽기 경험을 담당한다. 가변 글꼴의 모든 축을 `location`에 명시한다. 디스플레이에는 큰 `opsz`, 본문에는 본문 크기에 맞는 값을 사용한다. Google Fonts(OFL)를 우선 사용한다. Fontshare는 링크로만 제공하며, 유료 글꼴을 제안할 때는 라이선스 안내와 렌더링한 무료 대안을 함께 제공한다.

**색상**(`references/color.md`): 색은 색상(hue)·채도·명도와 어떤 배경에 놓이는지를 함께 고려해 정한다. 팔레트 생성의 기준색(시드 색상)을 초기 팔레트에 넣는다. `palette_build` 옵션은 `identity.palette_build`에 지정한다. 독립적인 용도가 있는 색상에는 `extra`에 `"#hex:Name:usage"` 형식을 사용한다. 로고 색상은 16진수 값을 직접 쓰지 않고 팔레트의 역할로 지정한다.

## 5 중간 검토 메시지: 제시한 뒤 멈추기

보드 이미지 경로를 보여주고, 각 세트를 다음 형식으로 제시한다.

```text
### A — <세트 이름>   ← 추천
<디자인 원리 한 문장.> <경쟁사와 다른 점.>
로고: <아이디어> · 타이포그래피: <디스플레이 / 본문> · 색상: <이름을 붙인 색상 2–3개>
검사: <통과한 필수 검사 또는 실패한 항목> · <알아둘 경고, AI 기본값 플래그와 사용 이유>
```

이어서 “세트를 하나 고르거나, 서로 다른 세트의 구성 요소를 조합해 달라고 요청해 주세요. 선택한 구성으로 가이드라인 키트를 만들겠습니다.”라고 안내한다.

## 6 정직한 설명

- 필수 검사는 대비, 라이선스, 글리프 지원 범위, 파일 유효성, 렌더링처럼 측정 가능한 실패를 다룬다. 경고는 보정되지 않은 경험적 규칙이므로 언급할 때 그 성격을 밝힌다. `rationale[]`의 `evidence`에는 스크립트나 사이트에서 확인한 값인 `measured`, 자신의 판단인 `judgement`, 또는 연구 근거 수준인 `strong | limited | practice`를 사용한다.
- 색상이나 글꼴이 “전환을 일으킨다”, “신뢰를 만든다”고 주장하지 않는다. 이런 연관성은 약하고 맥락에 따라 달라진다.
- 이유를 설명하며 옹호할 수 없는 세트는 보여주지 않는다. 승인을 받은 것처럼 꾸미지 않는다. 목업 데이터에는 그렇게 표시한다.
